secretless policy proxy for AI actions

AI action receipts at the tool boundary

An AI agent is good at proposing actions. It should not hold the credentials or define the boundary around them. CanaryNorth puts a narrow checkpoint between the proposal and the tool, decides whether the action may proceed, and records the decision as tamper evident evidence.

Ask.Check.Decide.Remember.

The model can knock. It cannot walk through.

Imagine a locked service door. An AI helper can bring a request to the door, but the boundary checks the badge and the request before anything moves. If the request is risky, a person can review it. The receipt is the logbook left at the door.

The agent never receives a real credential.

It holds an opaque reference like cap_weather_read_7f3d. The production credential stays on the trusted side of the boundary and never enters the agent's context.

Four things happen

Plain language first. Every request walks the same ordered path.

01 / ASK

Ask with a reference

The model presents a capability reference, not a provider credential. A convincing request is not authority.

02 / CHECK

Check the request

The boundary checks issuer, freshness, replay, the exact action and resource, and the content, in order, deny by default.

03 / DECIDE

Pause for a person

Higher risk changes can wait for a human yes or no. No answer means no action.

04 / REMEMBER

Leave a receipt

The record keeps the decision, the reason, and references, chained to the previous one. It never repeats the secret or the unsafe input.

The receipt ledger

Every decision, allow or deny, is appended and hash chained to the one before it. Change any earlier record and every hash after it stops matching. Secrets and unsafe input are never copied into the receipt.

real tools called in the demo

      

      
The 115 is a count of tested evaluator pairings, not 115 universal defenses. The 174 is the test count, not a claim of 174 independent controls. The boundary is deny by default: a request that clears every gate is the only kind that could reach a tool, and in the public demo that stops at would-forward-to-tool.
